Streaming World-Action Models for Robotic Manipulation

StreamWAM is a research framework and unified testbed for systematically studying streaming strategies in world-action-model-based robot control.

Its action-conditioned streaming formulation feeds the action prefix currently being executed back into the world model, so future video generation reflects robot motion already underway while the next world-action chunk is inferred asynchronously.

Research notes · August 2026

A streaming model should know what the robot is already doing.

World-action models connect visual prediction and action generation. StreamWAM asks what happens when that loop is reorganized around continuous robot execution—and why scheduling alone is not enough.

This page is a research preview rather than a substitute for the technical report. It develops the central motivation, explains the action-conditioned streaming design, and places the current results in context using the evidence available in the repository today.

01 · Motivation

Why Streaming WAM?

A robot does not experience inference and execution as separate benchmark columns. It experiences them as one control loop, with every pause translated into time during which the world may continue to change.

World-action models are appealing because they do more than regress an action from the latest observation. They generate a visual account of how the scene may evolve and connect that predicted future to a sequence of robot actions. This gives the controller a structured view of what its action chunk is expected to accomplish.

The usual infer-then-execute pattern, however, places model generation directly on the control path. The robot observes the scene, waits for a world-action chunk, executes that chunk, and then waits again for the following prediction. A stronger generative model does not automatically remove this stop-and-go rhythm.

Streaming changes the temporal organization of the loop. Instead of requiring one stage to finish before the other begins, the robot can execute the current action chunk while the model prepares what should happen next. The useful question is no longer only how fast one forward pass is, but how much of that work can happen while control remains active.

For streaming robot control, the model must predict ahead without losing track of the actions that are already changing the scene.

02 · The modeling gap

Execution overlap is necessary, but not sufficient.

Running inference and execution at the same time addresses waiting at the systems level. It does not by itself tell the world model which future is consistent with the motion already underway.

Consider a model that begins generating the next video and action chunk at the same moment that the robot starts executing its current chunk. By the time generation finishes, part of the current action has already affected the robot and possibly the scene. Yet a future generated only from the observation at the beginning of the interval does not explicitly encode that executed prefix.

This creates a temporal mismatch. The control process has advanced, while the conditioning context used for visual generation may still describe the beginning of the chunk. Overlap can therefore shorten idle time without fully coupling prediction to the state transition produced by ongoing execution.

StreamWAM treats this mismatch as a modeling problem. The action prefix is not merely metadata for a scheduler, and asynchronous execution is not added after the model has made an otherwise unchanged prediction. The executed action becomes part of the information used to construct the next visual future.

03 · Method

Action-Conditioned Streaming

The central design is simple to state: feed the action prefix currently being executed back into the world model, then condition future video generation on that prefix.

At a streaming boundary, StreamWAM knows the observation that initiated the current chunk and the portion of the action sequence that the robot is executing. The action prefix provides a compact account of the intervention being applied to the scene during model inference.

The model uses that action information when generating its visual future. In this way, the predicted frames are not only extrapolations from the previous image; they are futures constrained by how the robot is already moving. Action prediction is then attached to a visual trajectory that reflects the ongoing control process.

This is the distinction between model-level coupling and systems-only overlap. The scheduler determines when generation happens, while action conditioning changes what the model generates. StreamWAM combines both: asynchronous computation creates the opportunity to stream, and action-conditioned video generation aligns the prediction with execution.

The figure is deliberately read from execution toward prediction. The causal context begins with the action already applied by the robot, flows into the generated visual future, and ends with the next world-action chunk. This ordering is the core of the method.

04 · Control loop

Streaming While Acting

StreamWAM prepares the next decision during the time in which the current decision is being carried out.

The robot first receives a world-action chunk and begins executing it. Once streaming inference starts, execution does not pause. The growing executed prefix is made available to the model as the relevant action context for predicting beyond the current chunk.

While the robot continues moving, the model generates an action-conditioned visual future and the next action sequence. At the next handoff, the prepared chunk can become the current chunk. The pipeline repeats without describing the model and robot as two isolated processes.

The timing objective is therefore end-to-end continuity rather than a single kernel speedup. Faster model execution helps, but the control benefit also depends on whether prediction fits within the execution window and whether the resulting chunk remains successful when deployed.

05 · Framework

A Common Testbed for Streaming Strategies

StreamWAM is also a framework for asking the same streaming question across different world-action backbones and robot benchmarks.

Sequential WAM execution establishes the familiar reference point: inference completes, the robot executes, and the next prediction begins afterward. This makes information flow straightforward, but model latency appears directly as waiting in the control loop.

Execution-overlap strategies move inference into the action window. They can reduce idle time by scheduling the next prediction earlier, even when visual generation remains conditioned in the same way as the sequential model. This separates the benefit of overlap from the effect of changing the model context.

StreamWAM adds action-conditioned streaming. The next future is generated with knowledge of the action prefix underway, coupling the control schedule and the model input. Comparing these strategy families under common interfaces helps distinguish raw inference speed, end-to-end execution time, and task success.

The repository applies this view across LIBERO, RoboCasa, and RoboTwin. The backbones and evaluation protocols differ, but the organizing question remains consistent: how should a WAM predict its next chunk while the robot is still acting?

06 · Evidence

What the Current Results Show

Task success and control time are reported together. This matters because a streaming system that is fast but unreliable, or accurate but unable to keep pace with execution, does not resolve the original control problem.

StreamWAM models are initialized from FastWAM-Joint and further trained. The RoboCasa study builds on X-WAM, while the RoboTwin study builds on StarWAM. These lineages make the streaming comparison part of existing world-action-model families rather than a detached controller.

The tables below preserve the current reported values. They are shown in full—without interactive tabs—so the evidence remains readable as one continuous argument.

07 · Discussion

Where This Leaves Us

StreamWAM reframes streaming as a relationship between execution and prediction, not only as a way to schedule the same computation earlier.

The first provisional conclusion is that action conditioning provides a direct link between the robot motion underway and the visual future used for its next decision. It gives asynchronous prediction a model-level account of what execution is doing during inference.

The second is that streaming performance needs to be read jointly with control success. Chunk time, end-to-end time, and task outcomes describe different parts of the system; none alone establishes that a robot can act continuously and successfully.

The third is about the scope of this preview. The technical report will carry the broader analysis, limitations, and failure cases. Until then, this page presents the method motivation, released artifacts, evaluation protocols, and current tables without filling those missing sections with speculative claims.
